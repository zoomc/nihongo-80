## 1. 子 Agent / subagent 是否真实存在、如何调用、是否隔离会话上下文

### 1.1 CodeBuddy Code CLI —— ✅ 确认支持（文档最完整）

原文依据（`docs/cli/sub-agents`）：

- 「CodeBuddy Code 中的自定义子代理……通过提供具有自定义系统提示、工具和**独立上下文窗口**的特定任务配置」
- 「每个子代理：**使用与主对话分离的自己的上下文窗口**」
- 「**上下文保留**：每个子代理在自己的上下文中运行，**防止主对话被污染**」
- 「**性能考虑**：子代理**每次调用时都从干净的状态开始**」
- 「恢复时，代理**继续使用其之前对话的完整上下文**」

**调用方式（文档明确列出的四种）**：

| 方式 | 原文/说明 |
|---|---|
| 自动委派 | 「CodeBuddy Code 根据……您请求中的任务描述、`description` 字段、当前上下文和可用工具」主动委派；建议 description 里写 "use PROACTIVELY" / "MUST BE USED" |
| 显式调用 | 「使用 code-reviewer 子代理检查我最近的更改」 |
| `/agents` 界面 | 查看/新建/编辑/删除/配置工具权限与 per-Agent 模型 |
| 定义文件 | 项目级 `.codebuddy/agents/*.md`、用户级 `~/.codebuddy/agents/*.md`（Markdown + YAML frontmatter）；或 `--agents '{...}'` CLI JSON；或插件 `agents/` 目录 |

**状态/记忆相关字段（原文）**：

- `memory`：「持久记忆作用域：`user`（`~/.codebuddy/agent-memory/<name>/`）、`project`（`<cwd>/.codebuddy/agent-memory/<name>/`）、`local`（不进版本库）。启用后 spawn 时自动注入 `MEMORY.md`（**截断 200 行 / 25KB**）」
- 可恢复：「每个子代理执行都被分配一个唯一的 `agentId`；对话存储在 `agent-{agentId}.jsonl`；通过 `resume` 参数提供 agentId 恢复」
- `background: true` + `run_in_background: true` + `TaskOutput` 后台任务状态（pending/running/completed/failed/cancelled/killed）
- `maxTurns`、`tools`、`disallowedTools`、`permissionMode`、`effort`、`mcpServers`、`skills`、`disable-model-invocation`

**限制（原文）**：嵌套深度封顶 **5 层**；每根会话树默认最多 **20** 个并发子代理；每会话 spawn 预算默认 **200** 次；同步前台调用**默认不限时**（需 `CODEBUDDY_SUBAGENT_TIMEOUT_MS` 才启用超时）。

### 1.2 企业智能体 CloudAgent —— ⚠️ 字段存在，机制未核实

- `docs/workbuddy/.../CloudAgent` 的 Manifest 能力配置表中确实有 **`subagents: Subagent[]`「可调用的子 Agent」**字段（✅ 字段存在）。
- 同页 Session 定义：「一个 Runtime 下可以有多个 Session，**每个 Session 维护独立的对话历史和 Agent 上下文**」；Session 章节：「每个 Session 拥有**独立的对话历史和文件存储**」。这是 **Session 级**隔离，不是 subagent 级。
- 高级配置：「**记忆**：开启后 Agent 会记住多轮对话中的重要信息，**跨轮次**保持上下文」——是同一 Agent 内跨轮次，不是跨任务。
- ❌ **未能核实**：`subagents` 字段的**具体调用语法、子 Agent 之间是否隔离上下文、子 Agent 如何返回结果**，官方文档未展开。**按不可用处理**，不据此设计。

### 1.3 桌面端 WorkBuddy App —— ⚠️ 仅提及，机制未核实

- `Task-Management` 页：「**保存到工作空间**：将任务保存到工作空间，**可开启多个 Agent 同时协作**，在任务列表中持久保存，并支持通过 IDE 打开查看」。
- 腾讯云系统设置页（`tencentcloud.com/zh/document/product/1316/84502`）：「**智能体团队管理**：遇到复杂任务时自动组建多个智能体分工协作完成。禁用后所有任务将由单个智能体独立处理」。
- ❌ **未能核实**：桌面端"多个 Agent 协作"的**调用方式、上下文是否隔离、是否为真正的 subagent**。文档只提一句，无专门页面。**按不可用处理**。

**小结**：CLI 子代理是真实、可调用、明确隔离上下文的能力；但它属于命令行产品线，且「每次从干净状态开始」——**它不是平台替你自动传递教学状态的机制**。

## 2. 是否存在可持久化的"任务/会话状态"由平台自动管理

### ✅ 确认支持的部分：平台管理"任务/对话/产物"级状态

| 项 | 原文依据 |
|---|---|
| 任务状态机 | `Task-Management`：「进行中 / 已完成 / 失败 / 待处理 / 规划中 / 已归档」；侧边栏还有「已完成未读 / 待确认」标记 |
| 任务列表持久化 | 「左侧边栏会显示您创建过的任务」「空间：按工作空间整理的任务，方便您在同一个项目下集中查看历史任务」；「保存到工作空间……**在任务列表中持久保存**」 |
| 同一任务内上下文连续 | 「在已有任务中继续发送消息，WorkBuddy 会**基于之前的上下文继续处理**」；`Conversation`：「WorkBuddy 会结合当前对话上下文处理后续消息，无需重复描述已有背景」 |
| 产物与文件 | `Results`：产物 / 网页 / 工作空间文件 / 变更 四类视图；「变更视图用于查看当前任务带来的文件修改」 |
| 回退/编辑/刷新 | `Conversation`：可回退到某条消息之前（**对话与产物一起回退**）、编辑后重新开始、刷新最后一条回复；「**仅用于本地任务，云端任务和项目任务不提供**」 |
| CLI 定时任务持久化 | `docs/cli/scheduled-tasks`：「启用持久化的任务会**写入项目目录**，并在 CodeBuddy Code 重启后恢复」；持久任务有专属任务会话，「会话 ID 由任务 ID 确定性派生……会话数量等于持久化任务数量，不随执行次数或进程重启增长」 |

### ❌ 不支持 / 未承诺：应用自定义结构化状态

- 全部文档**没有任何一处**说明平台会自动管理、查询或传递用户自定义的**结构化教学状态**（例如 FSRS 的 `D/S/R/due`、掌握门控计数 `delayed_pass_count`、错题分类 `error_category`）。
- 平台持久的是「对话历史 + 产物文件 + 任务状态标签」，不是「可查询的应用状态数据库」。
- 尤其注意：`Conversation` 的上下文连续是**同一任务会话内**的；定时任务每次触发是**新发起的一次任务**（`Automation-Guide`：「到达执行时间后……**自动发起任务**」），文档**未承诺**把上一次运行的状态注入新任务。

**结论（对应设计决策）**：**每日教学状态必须由项目文件 + 脚本自行持久化**。平台不会自动传递。依据见第 6 节。

## 3. 定时任务 / 自动化（automation / 调度）是否存在、触发方式

### ✅ 确认存在（三套实现，且比预期完整 —— 如实记录）

#### (a) 桌面端「定时任务」（`Automation-Guide`）

- 入口：左侧导航栏「定时任务」，两个标签页「定时任务」「运行记录」。
- 创建方式：**手动新建 / 从任务新建（自然语言："帮我创建一个定时任务：…"）/ 从模版新建**；「在普通对话中直接描述周期性需求……WorkBuddy 同样会帮你创建定时任务」。
- 配置项：**名称、提示词、模型/专家/技能/连接器、工作空间（「指定任务执行目录及文件保存位置」）、权限、重复、时间、有效期、消息推送到企业微信**。
- 重复频率：**间隔 / 单次 / 每天 / 每周 / 每双周 / 每月 / 每年**；每周/每双周可多选星期，每月可多选日期。
- 触发方式：**按时间规则触发**（「任务**仅在设定的时间规则触发时执行**」）；另有「**立即运行**」（不影响原计划）、App/小程序的「**测试运行**」。
- 执行身份：「到达执行时间后**以您当前的登录身份自动发起任务**」。
- 三种来源：**本地**（本机客户端执行）/ **项目** / **云端**（云端沙箱，「无需电脑在线」）。
- 管理与通知：暂停/开启、编辑、查看运行记录、打开任务进入该次运行的会话、删除、批量管理；电脑端系统通知、手机端 App 通知（标题以「定时任务：」开头）。

**官方列出的限制（逐条，直接影响可靠性）**：

1. 「**本地定时任务在本机客户端中执行，执行期间请勿关闭电脑或退出客户端，否则任务可能中断**」
2. 「**云端沙箱无法访问本机文件**，请勿在提示词中引用本地文件路径」
3. 权限：「**完全访问权限（推荐）**：任务无人值守执行，工具调用无需逐次确认；开启时需再次确认」；「**默认权限**：敏感操作需要你确认；**如果你不在电脑前，任务会停在等待确认状态**」
4. 「受**任务频率、最大执行时长与系统并发控制**限制」（**具体数值文档未给出 → 未能核实**）
5. 运行失败原因举例：「连接器未授权、**登录已失效、电脑离线导致错过执行时间**、模型排队重试耗尽」
6. 「本地文件读写：**仅在您指定的工作目录范围内访问**」
7. 安全提醒：「任务在无人值守下自动执行，**请审慎设置涉及文件写入 / 删除 / 资金操作的提示词**」「大模型……可能存在理解偏差或非预期行为，对结果中涉及文件改动、数据变更、对外发送的部分，**请保留可追溯的日志**」

#### (b) CodeBuddy Code CLI 定时任务（`docs/cli/scheduled-tasks`）

- `/loop [间隔] <指令>`（支持 s/m/h/d，省略默认 10 分钟）、一次性自然语言提醒、`CronCreate` / `CronList` / `CronDelete`、5 字段 cron 表达式（可由 AI 自然语言转换）。
- 触发：「任务到点后会进入队列，并在**会话空闲时**开始执行；同一任务同一时刻最多保留一个排队中或执行中的实例，若下一调度到达时上一实例仍未结束，**本次触发会跳过**」。
- **持久化**：「通过对话创建的定时任务**默认是会话级别的，CodeBuddy Code 退出后自动清除**。在 Web UI 创建或编辑任务时，可以启用持久化，使任务在重启后继续生效」；持久化任务「写入项目目录」「会话 ID 由任务 ID 确定性派生」。
- **关键限制（原文）**：
  - 「**循环任务在创建 3 天后自动过期删除**，过期前会最后触发一次」「如果需要任务持续更长时间……**改用外部调度方案（如 GitHub Actions 等）**」
  - 「**不补跑**：会话中断期间错过的任务不会补发执行」
  - 最小间隔 1 分钟；每会话最多 50 个定时任务
  - Jitter：循环任务最多延迟周期 10%（上限 15 分钟），一次性整点/半点任务最多提前 90 秒
  - `CODEBUDDY_DISABLE_CRON=1` 可整体禁用

#### (c) 移动端 / 小程序自动化

`docs/workbuddyapp/features/Auto`（App，云端）、`docs/workbuddymini/features/Auto`（小程序）：表单创建或对话创建，字段为标题/提示词/执行频率/执行时间，支持**编辑、测试运行、暂停/恢复、删除**、查看历史执行记录，完成后 App 通知（需开启通知权限）。文档注明「以下内容是在**云端工作**下的配置指引。**连接电脑**下的自动化用于**接收**电脑端自动化任务执行结果」。

### ⚠️ 未能核实（按不可用处理）

1. 桌面端定时任务是否支持**任意 cron 表达式**（自动化页只列频率选项；cron 表达式明确写在 **CLI** 文档里，不能算到桌面端）。
2. 定时任务触发时，平台是否**自动注入上一次运行的产物/状态文件**——所有页面均未提及。**按不可用处理**。
3. 「最大执行时长」「系统并发上限」的具体数值——文档只写"受限制"，未给数字。

> **重要澄清**：定时任务能做的是「**到点自动发起一次 Agent 任务**」，不是「**自动把昨天的教学进度续上**」。后者取决于提示词是否显式要求 Agent 去读项目文件，平台不承诺。

## 4. 本地文件系统读写、脚本执行能力

### ✅ 确认支持（桌面端 / CLI）

| 能力 | 原文依据 |
|---|---|
| 本地文件读写 | `Overview` 核心能力：「**本地文件操作**：在获得授权后读取和处理本地文件，支持批量整理、修改等操作」 |
| 指定工作目录 | `Create-Task`：「点击输入框左下角的**选择工作空间**……WorkBuddy 会**基于该目录读取和处理文件**」 |
| 本地处理 / 隐私边界 | `Conversation`：「**所有文件处理默认在本地完成，原始数据不上传云端**」「服务端仅处理数据片段，用后即弃，不保存也不用于模型训练」「**WorkBuddy 只能访问你主动勾选授权的文件夹，系统敏感目录自动拦截，高危操作需二次确认**」 |
| 上传/引用上下文 | 支持 PDF/Word/TXT/Markdown/Excel/CSV/TSV/PPT/图片/ZIP/常见代码文件；`@` 引用文件/文档/规则；粘贴截图 |
| **终端 / 脚本执行** | `Results`：「**打开终端**：打开终端标签页，**执行命令行操作**」；「变更」视图说明「如果任务涉及**代码开发、脚本生成或配置调整**，建议优先在这里确认改动」 |
| 工作空间文件浏览 | `Results`「工作空间文件」视图：左侧文件树 + 右侧文件内容 + 已打开文件切换栏，「检查任务是否写入了正确的位置」 |
| 本地路径操作 | `Results`：「**打开文件夹**」「**复制路径**」「另存为」「在默认应用打开」；`Task-Management`：「打开文件夹」「在 CodeBuddy 打开」 |
| 技能内可执行脚本 | 官方开放平台 `open.workbuddy.cn/docs/skill` 的技能结构含 **`scripts/`（可执行脚本）**；`workbuddy.ai/docs/ide/Features/Skills` 明确 `scripts/` 用于 **"Executable code for tasks requiring deterministic reliability or that are repeatedly rewritten"** |

### ⚠️ 边界与限制

- **云端定时任务沙箱无法访问本机文件**（`Automation-Guide` 原文），所以「定时任务 + 本地状态文件」**只能选本地来源的任务**。
- `Conversation` 的回退/编辑/刷新「**仅用于本地任务，云端任务和项目任务不提供**」。
- 文件访问范围受授权文件夹限制，高危操作需二次确认。

**结论**：把确定性脚本（如 `update_state.py`、`build_queue.py`）放在项目工作空间、由 Agent 调用或在终端执行，是官方文档明确支持的能力，可作为本项目状态持久化的技术基础。

## 5. 长期记忆（跨会话）的实际机制与限制

### ✅ 确认存在（`docs/workbuddy/.../Memory` 页 + 腾讯云 `cloud.tencent.com/document/product/1831/134444`）

**机制（官方原文）**：

- 「**记忆**功能从您的**会话历史**中提取具有参考价值的个人信息（**事实信息、偏好习惯、人物关系、近期跟进事项等**）形成「记忆数据」并**定期更新**。后续对话或任务执行时，会将与当前请求相关的记忆**作为背景信息一并参考**」
- 「**提取频率：每晚整理当天会话**，仅您本人可见」
- 使用方式：「1. **注入系统提示词作为上下文**；2. **支持对会话历史的检索**（如「上周做过什么」「之前聊过的 XX」）」
- 收集范围：「从会话内容中**由模型自动抽取**的事实信息、偏好习惯、人物关系、跟进事项等」
- 用户控制：「默认开启」「可在头像 → 设置 - 记忆中**查看、编辑、删除或一键关闭**」「支持**从其他 AI 导入记忆**」「关闭或删除记忆条目后，相应数据将停止用于后续对话，**但已生成的输出不会因此追溯撤回**」
- 积分：「记忆提取由 WorkBuddy 自费完成，不向您额外消耗 token / 积分」；第三方共享：「不涉及」

**官方明示的限制（关键）**：

- 「记忆由模型基于会话内容自动抽取，**可能存在概括偏差或时效性问题，在依赖记忆做重要判断前建议先核验**」
- 「记忆摘要**每晚重新生成**」（非实时）
- 仅本人可见；涉及他人个人信息需先获授权

### ⚠️ 未能核实 / 需谨慎

- 腾讯云**系统设置页**（`tencentcloud.com/zh/document/product/1316/84502`）另提到「**本地记忆**：将日常工作记忆写入**本地文件**，跨会话保留上下文」以及「本地技能与记忆沉淀：自动记录本地记忆、工作日志……数据本地存储」。该描述来自**腾讯云系统设置文档**，与 WorkBuddy 主文档站的 Memory 页描述（模型抽取 + 提示词注入）**不完全一致**；本次未在 WorkBuddy 主文档逐字核实该「本地记忆写文件」机制，**标注为未能核实，不纳入设计依据**。
- 记忆是否支持**用户自定义结构化字段 / API 读写**——文档只写查看/编辑/删除/关闭/导入，**未提及** → 未能核实。
- 企业智能体的「记忆：开启后……跨轮次保持上下文」是**同一 Agent 会话内跨轮次**，不等于跨任务长期记忆。

### ❌ 明确不能依赖记忆的场景

记忆是「**模型自动抽取 + 注入系统提示词 + 每晚批量生成 + 可能有概括偏差**」的个性化背景，**绝不能**用来承载：

- FSRS 的 `D / S / R / due` 精确数值
- 掌握门控计数（`delayed_pass_count`、`distinct_contexts`、`assessment_version`）
- 错题分类 `error_category`、复习队列、单元解锁状态

理由：官方自己要求「依赖记忆做重要判断前建议先核验」，且它是提示词注入而非结构化存储，无法保证数值精确、无丢失、可审计。**这些必须放在项目文件里由脚本读写。**

## 6. 面向设计决策的结论

### 6.1 核心结论（与任务给定判断一致，并给出文档依据）

> **本项目的每日教学状态必须靠「项目文件 + 脚本」持久化，平台不承诺自动传递。**

逐条理由（每条都对应上面核实过的原文）：

1. **平台自动管理的是"任务/对话/产物/任务状态标签"**，不是应用自定义结构化状态（§2）。所有官方文档均无"跨任务自动传递自定义状态"的说明。
2. **定时任务的语义是「到点自动发起一次任务」**（`Automation-Guide` 原文「自动发起任务」），不是「自动续上昨天的进度」。是否读到昨天状态，完全取决于**提示词是否显式要求 Agent 去读 `items.json`**；文档未承诺自动注入（§3）。
3. **记忆是模糊的、提示词注入式的、每晚生成的、可能有偏差**，官方要求"重要判断前先核验"（§5），无法承载精确数值状态。
4. **CLI 子代理"每次调用都从干净的状态开始"**，恢复需要显式 `resume` + `agentId`（§1.1）——不是自动状态传递。
5. **云端沙箱不能访问本机文件、本地任务需电脑在线**（§3/§4），自动化本身有可用性前提。
6. **CLI 定时任务循环任务 3 天自动过期、且不补跑**（§3b），长周期无人值守不可靠。

因此：**状态文件是唯一可信来源（single source of truth）**，AI 每次会话都从文件读取、把变更交给脚本写回。

### 6.2 哪些环节只能人工启动（明确清单）

| 环节 | 为什么只能人工 | 依据 |
|---|---|---|
| **首次创建/配置定时任务**（填提示词、选工作空间、开启"完全访问权限"、先"立即运行"试跑） | 文档给的创建方式全是人工/对话发起 | `Automation-Guide`「点击页面右上角的新建」、使用建议「新建任务后建议**先点击运行试跑一次**」 |
| **保证本地定时任务可运行**：电脑不关机、客户端不退出、登录态有效、授权文件夹已勾选 | 官方列明中断/失败条件 | 「执行期间请勿关闭电脑或退出客户端」；失败原因含「登录已失效、电脑离线导致错过执行时间」 |
| **不使用定时任务时的每日教学会话** | 无自动触发器 | — |
| **定时任务失败后的重试 / 调整执行时间 / 补跑** | CLI「不补跑」；桌面端需手动重试 | `docs/cli/scheduled-tasks`「不补跑」；`Automation-Guide`「考虑调整执行时间后手动重试」 |
| **敏感操作 / 文件写入删除的二次确认** | 默认权限下无人值守会卡在"等待确认" | 「默认权限：敏感操作需要你确认；如果你不在电脑前，任务会停在等待确认状态」 |
| **记忆的核验与纠错**（把模糊记忆改成精确状态） | 官方建议"重要判断前先核验" | `Memory` 使用建议 |
| **FSRS 参数优化、状态文件校验与纠错、平行卷生成、单元解锁判定** | 属自定义确定性逻辑，平台无对应自动机制 | §2 结论 |
| **云端/本地任务来源切换、企业微信推送绑定** | 需人工在编辑窗口配置 | `Automation-Guide` |

### 6.3 如果仍然选择启用定时任务（可选项，不是平台保证）

按文档能做到的最稳妥配置：

```
来源 = 本地（不能选云端沙箱，否则读不到本机 items.json）
工作空间 = /Users/mj/Documents/learn/jp/nihongo-80
权限 = 完全访问权限（否则无人值守会停在待确认）
重复 = 每天 / 固定时间
提示词第 1 句 = "先读取 research/items.json 与 research/session-log.jsonl，
              按 scripts/build_queue.py 生成今日队列；所有状态变更只通过
              scripts/update_state.py 写回，不要自己改 JSON"
创建后 = 人工点「立即运行」试跑一次，确认产物与状态文件符合预期
```

并明确接受：电脑离线/客户端退出会漏跑、循环任务（CLI）3 天过期、不补跑、并发/最大时长限制数值未核实。**基线设计仍应是"人工启动 + 文件持久化"，自动化只是可选加速。**

### 6.4 确定性程序 vs AI 分工建议

官方依据：`workbuddy.ai/docs/ide/Features/Skills` 明确 `scripts/` 用于 "**Executable code for tasks requiring deterministic reliability or that are repeatedly rewritten**"；开源项目 `m98/fluent`（MIT，见 `learning_science.md` §2.3）已给出可复用范例——它把 SM-2 计算、DB 更新、反馈格式做成 **helper Skills / `update-db.py`**，把教学对话留给 AI。

| 交给**确定性程序 / 脚本**（必须） | 交给 **AI**（适合） |
|---|---|
| `items.json` / `session-log.jsonl` 的读写、原子更新、备份（可由 Hooks 触发） | 出题措辞、语境创设、例句与对话生成 |
| FSRS 调度计算（R/D/S、`I(r,S)`、due 日期）、评分 1–4 映射 | 开放式产出（造句/作文）的质量评价、错误归因与讲解 |
| 答案规范化与判分（exact / normalize）、计时 | 补救教学（corrective instruction）的**不同讲法**、平行卷内容生成 |
| 掌握门控判定（阈值 0.85、延迟/次数/语境条件）、单元解锁 | 从诊断结果决定"今天重点讲什么"、节奏与动机引导 |
| 队列构建（due 筛选、交错/blocked 规则、相邻 tag 不重复、Daily cap） | 可理解输入材料的**选篇润色**（生词率由脚本先筛） |
| 状态校验、幂等、日志追加、`known_token_ratio` 分词统计 | 学习者偏好 / 风格等**非精确**背景（可交给记忆，但不作判定依据） |
| 一致性检查（反馈三要素是否齐全、平行卷 version 是否递增） | 解释"为什么错"、类比与记忆法 |

**一条硬规则**：凡是要写进 `items.json` 的数值，一律由脚本写入；AI 只输出"评分 + 错误类别 + 讲解"给脚本消费。这样即使模型产生偏差，状态文件仍然可审计、可回滚、可跨会话复用。
