# Nihongo 80 · 学员视角可用性审计（Day 001）

- **审计对象**：`web/day-001.html`（内嵌 `#nh80-site` / `#nh80-day`）、`web/data/day-001.json`、`web/assets/app.js`、`web/assets/app.css`、`curriculum/day-001.md`、`web/day-050.html` + `web/data/day-050.json`
- **学员画像**：中文母语、有韩语背景、**日语零基础**。目标很朴素——「今天我要学会几句日语」。
- **触发原话**：「网页版啥玩意儿啊，太抽象了，我都看不懂……单词、语法、例句、发音、适当的难点讲解、记忆曲线科学复习、练习，至少得覆盖这些吧，可以适当对照下韩语类似语法」。
- **一句话结论**：页面不是「没内容」，而是**把可学内容全部折叠/翻面/藏到提交按钮之后，把系统元信息全部铺在首屏**。零基础学员连滚 3 屏，看到的是进度条、图表、术语和考试题干，**看不到一个带读音、中文义、例句、发音按钮的日语单词**。内容存在，但对学员不可见、不可学、不可验收。

### 1.2 环境坑（如实记录，保证可复现）

1. 会话内存在 `HTTP_PROXY=http://127.0.0.1:51843`，会让 urllib / websockets 把本地 CDP 请求走代理，产生 `502 Bad Gateway` 和 WebSocket `1006` 断连。脚本中清空了全部 `*_PROXY` 并设 `NO_PROXY=127.0.0.1,localhost`。
2. 沙盒环境里 Chrome 报 `sandbox initialization failed: Operation not permitted`，随后 `GPU process isn't usable. Goodbye.`（GPU 进程反复崩溃导致浏览器退出，进程 `poll() = -5`）。故加 `--no-sandbox` 与软件渲染三件套。这是**审计环境**限制，与项目无关，不影响页面本身。
3. Chrome 版本 `Chrome/156.0.8078.80`。headless 下 `speechSynthesis` 存在但 `getVoices()` 无 `ja-JP`，因此 `document.body.className` 实测为 `is-wide no-ja-tts` / `is-narrow no-ja-tts`（见 `*-probe-*.json`）。**这是重要的观测差异**：因为 `web/assets/app.css:182-183` 的 `.front-kana{display:none}` / `.no-ja-tts .front-kana{display:block}`，headless 里词汇卡正面**反而显示了假名**；真机若装有日语语音，正面假名会被隐藏，只剩汉字（如「私」）。也就是说，真实设备上比截图**更不友好**。

### 3.1 N3 阶段是否更抽象（`web/data/day-050.json` / `web/day-050.html`）

**是，明显更抽象**，且抽象程度随阶段上升：

- 页面 `h1` 直接是一串语法术语：`意见陈述｜V辞書形 / Vない形 + ことが ある・V意志形 + と 思う / と する・関係`（`day-050.html:72` 内嵌 `theme`，与 `day-001.html` 同构）。
- 接续全是日语术语：`動詞 辞書形／ない形 + ことが ある；ある 可变形…`、`動詞 意志形（五段 お段+う／一段 よう／する→しよう／来る→こよう）`。零基础（甚至 N4）学员看到「五段 お段+う」无法解码。
- 能力目标 / Can-do 复述同一串术语；`focus: ["production","grammar"]` 仍是英文。
- 题目 `rationale` 引用**内部语法 ID**：`「V辞書形＋ことがある」＝有时会（G0066）；「Vた形＋ことがある」＝曾经做过（G0042）` —— 学员不知道 G0066/G0042 是什么，等于用编号解释编号。
- 素材是整段商务邮件（`件名：あしたの会議の時間について／田中様 お疲れさまです…`）与医院对话，**无假名、无翻译、无生词注释**，比 Day 1 的短句难得多，但讲解支持没有相应增加。
- 汉字 `zh_trap` 里出现「入声 -ク」「七曜借自行星名」等音韵/词源术语，对零基础是额外负担。

结论：现有页面抽象度不随学员水平下降而下降，反而随语法复杂度上升而上升；Day 1 的问题在 Day 50 是**放大**而非缓解。

## 6. 可验收的改造清单

### 6.0 目标态：从「今天我要学会几句日语」出发，理想的一屏长什么样

**区块顺序（自上而下，不折叠、不翻面、不滚动即可学完第一句）**：

1. **今天要会的 3 句话**（最大字号，日 + 假名注音 + 中文 + 「听」按钮）
   - `おはようございます。` / `おはようございます` / 「早上好（礼貌说法）」 / 🔊
   - `私はリンです。` / `わたしはリンです` / 「我是小林」 / 🔊
   - `よろしくお願いします。` / `よろしくおねがいします` / 「请多关照」 / 🔊
   - 每句下挂一行「逐词」：`私(わたし)=我` `は=提示主题（读 wa）` `リン=人名` `です=礼貌体的「是」`。
2. **今日 6 个词**（卡片常显，不翻面）：每词 = 汉字/假名 + **假名注音** + 罗马音或音调 + **词性** + 中文义 + **1 个带中文翻译的例句** + 🔊 听 + 「韩语对照」（如 `さん ≈ 씨`、`こんにちは ≈ 안녕하세요`）。
3. **今日 1 条语法**：用中文讲——「A は B です = A 是 B；は 读 wa，不读 ha；です 是礼貌体，朋友之间可省略」；接续写「名词 + は + 名词 + です」并给中文注释；2 条例句各带假名与翻译；**易错点**明确写「中文说『我是李先生』可以，日语不能给自己加 さん」「中文没有助词，日语的 は 不能漏」；附 **韩语对照**「は ≈ 은/는，です ≈ 입니다/이에요，语序同为 SOV」。

## 7. 哪些现有设计值得保留（别改坏）

以下都是真实核实过的优点，改造时**必须保留**，且第 6 节的方案不应破坏它们：

1. **零 CDN、零外部请求、纯静态 `file://` 可打开**：`web/day-001.html:18,73` 只引本地 `assets/app.css` / `assets/app.js`，数据内嵌在 `<script type="application/json">`，`app.js:1-5` 明确「不发起网络请求」。离线可用、无追踪、无账号。
2. **离线能力 + Service Worker 降级**：`sw.js`、`manifest.webmanifest`、`app.js:75-78` 对 `file://`/不安全上下文自动跳过注册，`app.js:250-259` 有在线/离线状态提示。
3. **回传码机制（`NH80R1`）与「状态真源在 SQLite」的架构**：`app.js:44-89, 736-763` 用 base64url 编码结果，本地 `import-web-result` 校验去重写库；`app.js:1097`、`site-footer` 明确「不会把『读完页面』记为完成」、`app.js:712-713` 缓存恢复提示明确写「不是学习状态真源，也不代表已完成」。**这套「不假装已掌握」的诚实设计非常珍贵，正是 P0-9 要延续而非推翻的东西**——问题只在于它同时也把学员首屏变成了架构说明页。
4. **不向服务器发送学习数据 / 不编造数据**：页脚三条声明；素材带 `license: original`，空值统一显示 `—`（`app.js:487`），答案与评分准则全部来自 `day-001.json` 的 `answer / rationale / rubric`，没有凭空生成的「正确率」「掌握度」。
5. **TTS 降级不静默失败**：`app.js:148-178, 601-602, 955` 在「无 ja-JP 语音 / 不支持 / 播放被拒」三种情况下都明确给中文提示并保留「文本 + 假名读音」，而不是悄悄无声。手势解锁 `primeTTS`（`app.js:139-147`）对 iOS/Android 是必要且正确的处理。
6. **双端适配的工程底子**：`isWide()` + `matchMedia('(min-width:900px)')`（`app.js:32-42`）切换 `grid` / `step`；`app.css:9, 76-102, 280-307` 的 44px 触控目标、16px 输入防缩放、`safe-area-inset`、深色模式、粘性顶栏与底部操作栏。这些不需要重做，只需把「一屏一题」从「先考试」改成「先学后练」（P2-3）。
7. **逐题即时判分 + 提示 + 评分准则 + 自评 + 错误归因**：`app.js:864-919, 1000-1020` 机制完整，且 `gradeAnswer` 对开放题返回 `null` 交给自评，是合理设计。**保留机制，只把表达教学化**（P1-5），并把「自评达成」从 `correct` 里拆出来（P0-9）。
8. **「先自测，再点开看读音与释义」的翻面卡意图**：主动回忆（retrieval practice）方向是对的，问题只在于**整个 section 默认折叠 + 必须翻面**导致内容不可见。建议保留翻面交互于「复习模式」，但「今日新词」必须常显（P0-2）。
9. **汉字卡的「中日差异」`zh_trap`**：`day-001.json` 三条与 `day-050.json` 两条写得扎实（音读/训读随词变、七曜、入声 -ク、相談≠互相谈话），是全站**唯一**符合用户「适当的难点讲解」的内容。应作为词汇卡/语法卡讲解区的模板推广，而不是删掉。
10. **数据层已具备改造所需字段**：`vocab.kana / meaning_zh`、`grammar.connection / example / meaning_zh`、`questions[].rationale / rubric / audio_text`、`materials[].text_ja / audio_text`、`kanji.zh_trap`。P0 多数条目是**把已有数据挪到首屏 + 补中文讲解**，不需要重造课程体系；`curriculum/day-001.md:34-35` 甚至已经写了「需复习的旧知识：无（首日或纯新课）」，只是没被渲染出来。

> 一句话守住的底线：**改造是「把已有的好内容从折叠/黑话后面搬到学员眼前」，不是推倒重来，更不是编造学习数据或把成绩写进网页。**
